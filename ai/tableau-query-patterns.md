# Tableau Query Patterns

This document describes the common SQL queries generated by Tableau Desktop when
connecting to a PostgreSQL-compatible data source.

The Skadi SQL Gateway should be tested against these patterns.

The goal is not full PostgreSQL compatibility, only the behavior required
for BI tools such as Tableau.

---

# Connection Phase Queries

When Tableau connects, it typically performs metadata discovery.

Examples:

SELECT * FROM information_schema.tables

SELECT * FROM information_schema.columns

SELECT * FROM pg_catalog.pg_tables

SELECT * FROM pg_catalog.pg_namespace

Purpose:

Discover schemas and tables available in the database.

The Skadi SQL Gateway must return valid responses to these queries.

Metadata can be generated from Databricks table metadata.

---

# Schema Discovery

Example queries:

SELECT
table_schema,
table_name
FROM information_schema.tables
WHERE table_schema NOT IN ('pg_catalog', 'information_schema')

Purpose:

Populate Tableau's schema browser.

---

# Column Discovery

Example query:

SELECT
column_name,
data_type
FROM information_schema.columns
WHERE table_name = 'gold_risk'

Purpose:

Determine table column structure.

---

# Sample Data Queries

Tableau often fetches small samples before building visualizations.

Example:

SELECT *
FROM mxl.gold_risk
LIMIT 100

Purpose:

Preview dataset structure.

---

# Aggregation Queries

Typical visualization query:

SELECT
cob_date,
SUM(pnl)
FROM mxl.gold_risk
GROUP BY cob_date

Purpose:

Compute metrics for charts.

---

# Filtered Queries

Example:

SELECT
cob_date,
book,
SUM(pnl)
FROM mxl.gold_risk
WHERE cob_date >= CURRENT_DATE - INTERVAL '30 day'
GROUP BY 1,2

Purpose:

Interactive filtering within dashboards.

---

# Top N Queries

Tableau frequently generates queries with LIMIT.

Example:

SELECT
book,
SUM(pnl) AS total_pnl
FROM mxl.gold_risk
GROUP BY book
ORDER BY total_pnl DESC
LIMIT 20

Purpose:

Top categories visualizations.

---

# Nested Query Pattern

Tableau sometimes wraps queries.

Example:

SELECT *
FROM (
SELECT
book,
SUM(pnl) AS total_pnl
FROM mxl.gold_risk
GROUP BY book
) t
ORDER BY total_pnl DESC

Purpose:

Sorting and ranking.

---

# Parameterized Queries

When filters change, Tableau re-runs queries with modified predicates.

Example:

SELECT
cob_date,
SUM(pnl)
FROM mxl.gold_risk
WHERE cob_date BETWEEN ? AND ?
GROUP BY cob_date

Purpose:

Interactive dashboards.

---

# Query Execution Expectations

The Skadi SQL Gateway must:

Accept the SQL query from the client
Forward the SQL to Databricks SQL Warehouse
Stream results back to the client

Execution pipeline:

Client
↓
Skadi SQL Gateway
↓
Databricks SQL Warehouse
↓
Arrow RecordBatch
↓
PgWire DataRow

---

# Caching Behavior

The Skadi gateway should cache query results using a deterministic key.

Cache key inputs:

normalized SQL
query parameters
dataset version

Example:

SELECT cob_date, SUM(pnl)
FROM mxl.gold_risk
GROUP BY cob_date

Running the same query twice should produce a cache hit.

---

# Example Cache Test

Cold run:

15 seconds

Warm run:

2 seconds

Cache hit should be logged.

---

# Error Handling

When a query fails, the gateway should return a PostgreSQL-compatible error message.

Example:

ErrorResponse
severity: ERROR
message: relation does not exist

Tableau Desktop
psql
DBeaver
DataGrip

---

# AI Implementation Guidance

When implementing support for Tableau queries:

Prefer compatibility over strict PostgreSQL semantics.

Only implement functionality required for BI connectivity.

Avoid implementing full database behavior.

The Skadi gateway is a protocol adapter, not a SQL engine.
